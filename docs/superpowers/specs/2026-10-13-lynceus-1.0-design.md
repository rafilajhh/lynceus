- **Date:** 2026-10-13
- **Status:** approved direction (brainstorming), spec pending review
- **Target:** 1st place, AMD Developer Hackathon ACT III, Track 1 *Intelligent Industry*
  (partner: Vibe Generation). Bar set by the team: "ready to be acquired by an
  industrial buyer as-is."
- **Hard deadline:** Sun 18 Oct 2026 12:00 CEST = **17:00 WIB**. Internal
  submit target: **18 Oct 12:00 WIB** (5 h buffer).

## 1. Problem and user

Cement plants in Indonesia co-process refuse-derived fuel (RDF). Every incoming
truck is checked by a weighbridge operator in 15–30 s. A missed metal chunk can
wreck a shredder (≈ Rp 350 jt, RDI 2024) or stop the kiln (≈ US$ 28k/h). The
operator *has* data — the photo, the waybill, the weighbridge, gas readings,
the plant SOP — the problem is the brief's own: **"knowing what matters and
what to do next."**

Primary user: the **weighbridge operator** (verdict in seconds, next step in
plain words). Secondary user: the **shift supervisor / AF (alternative fuel)
manager** (end-of-shift picture: what was caught, which suppliers cause it,
what it saved).

| Brief line | Lynceus 1.0 answer | Section |

| Working product, operator-readable | Public live URL, traffic-light verdict, "Live · AMD" provenance + latency on every result | 4.1, 6 |

Every row must be demonstrable in the video and clickable at the live URL.

## 3. Constraints and non-goals

**Constraints**
- AMD must run a *meaningful* part of the working product. All model inference
  in the live path runs on **AMD Token Factory** (OpenAI-compatible, AMD GPUs).
  No Gemini proxy in the submitted configuration.
- Token Factory team key is rate-limited and shared by teammates → all callers
  honour `Retry-After`, and batch jobs (benchmark) are throttled.
- Honesty is a product feature (PRODUCT.md principle 1): every number on
  screen has a source; demo/sample data is labelled; no measured-accuracy
  claim beyond what the benchmark measured.

**Non-goals (explicitly out)**: kiln/feed-mix prediction, Evolus agents,
fine-tuning, multi-tenant auth, real OCR of waybill images (stays
"accepted, not processed" — already documented), mobile app.

## 4. Components

Each unit has one job, a typed interface, and its own tests. New backend
modules live in `backend/src/lynceus/`.

### 4.1 Live AI on AMD (foundation)

- **Model roles** (env-configurable, defaults in `.env.example`):
  - `VLM_MODEL=DeepSeek-V4.1-Flash` — vision (only model validated to return
    coherent structured vision JSON on Token Factory).
  - `LLM_MODEL` for waybill cross-check: `DeepSeek-V4-Flash`.
  - `ASSIST_MODEL=Gemma-4-31B-IT` — text-only roles (Pythia, explanations).
    Gemma on AMD also makes the project eligible for the Google partner prize.
    If Gemma proves unusable for text too, fall back to `DeepSeek-V4-Flash`
    and drop the Google angle (decided by the D1 spike, §7).
- **Provenance on every AI output**: `provider: amd-token-factory`, model id,
  wall-clock latency (ms). Shown in the UI badge "Live · AMD Token Factory · 4.2 s".
- **Fail-closed in production config**: `LYNCEUS_ALLOW_STUB_FALLBACK=0` on the
  hosted demo for non-demo inspections; scripted demo cases remain available
  and are labelled "Scripted sample".
- **Fix the open gas-ingest WIP** (currently uncommitted in the main checkout)
  and land it on this branch: restore the `get_settings` import in
  `pipeline.py`; `GasOutput.source` handles "not measured"; `ai_outputs.gas`
  optional on read so v1 records still load; `gas_ingest` catches bad values;
  tests for no-gas inspections and `gas_ingest`. Drop the "Ecotec Sentinel"
  vendor wording (virtual twin must not name a real product).

### 4.2 Contaminant localisation

- VLM prompt additionally requests, per contaminant, a normalised box
  `[x0, y0, x1, y1]` in 0..1 and a label.
- `vision_boxes.py` validates boxes (range, ordering, min area, max count 8);
  invalid boxes are dropped, never "fixed up".
- UI overlays boxes on the photo with the label; the gate strip's VLM gate
  links to them.
- **Fallback if the D1 spike shows the VLM cannot localise reliably**: a 3×3
  zone grid (VLM names the zone), rendered as a highlighted cell. Spec is
  satisfied either way; the UI states which mode produced the marking.

### 4.3 Next-step card (decision → action)

- `actions.py`: a deterministic, table-driven mapping from
  `(verdict, failed gates)` to an ordered list of operator actions, each with
  an SOP clause id. Examples: REJECT+hard contaminant → "Do not tip. Route to
  sorting bay. Photograph and notify supplier. (SOP-RDF-4.2)"; ESCALATE+wet →
  "Hold ticket; request supervisor moisture check; apply moisture penalty if
  confirmed (SOP-RDF-5.1)".
- Deterministic on purpose: actions are auditable and identical for identical
  inputs; the LLM only *phrases the explanation*, never chooses the action.
- Actions are written into the audit record (`recommendation.actions`).

### 4.4 Pythia — operator assistant over manuals

- **Knowledge base**: `knowledge/` markdown files, each chunk carrying a stable
  citation id:
  - `sop-rdf-gate.md` — a reference gate SOP authored for this product,
    modelled on the plant flow in `docs/research/realcase-indonesia.md`;
    labelled "reference SOP" (not a real plant's document).
  - Regulation/standard notes already sourced in `docs/research/`
    (40 CFR 98 Eq. HH-1, AP-42 landfill-gas, EN 15359 scope, NIOSH limits).
- **Retrieval**: BM25 over chunks (pure Python, no vector DB — corpus is small;
  YAGNI). Top-k chunks + the current inspection's audit record go to
  `ASSIST_MODEL`.
- **Answer contract**: answer + list of citation ids; every citation id must
  exist in the retrieved set or the answer is rejected and Pythia says it
  cannot answer from the plant documents. No uncited claims.
- **API**: `POST /assist {question, record_id?}` → `{answer, citations[], provenance}`.
- **UI**: side panel on the console and on a ledger record ("Ask Pythia about
  this truck"), with 3 suggested questions.

### 4.5 Shift report + supplier risk

- **Input change**: `supplier` (string, from the waybill sender) becomes a
  first-class field of the inspection request and the audit record inputs.
- `shift.py`: pure aggregation over audit records in a time window: trucks,
  verdict counts, contaminants caught, Rp prevented (from `impact.py`),
  median seconds per truck, per-supplier reject/escalate rate.
- **Supplier risk ranking**: deterministic score (reject and escalate rates,
  min sample size shown). The `ASSIST_MODEL` writes a 2–3 sentence
  explanation + recommendation per flagged supplier, grounded only in the
  computed stats (stats are passed in; numbers in the text are checked against
  them).
- **API**: `GET /shift-report?since=&until=`.
- **UI**: new route `/shift` (console nav). Hosted demo is seeded with a
  sample shift clearly labelled "Sample shift — scripted data".

### 4.6 Audit record v2

- `format_version: 2` adds: `inputs.supplier`, `ai_outputs.*.provenance`
  (provider, latency_ms), `ai_outputs.vlm.boxes`, `ai_outputs.gas` (optional),
  `recommendation.actions`.
- Loader reads v1 and v2 (v1 fields defaulted, never rewritten). Writing is
  always v2. Digest rules unchanged. Existing invariant tests extended for v2.

### 4.7 Validation benchmark (the measurable claim)

- **Dataset**: RealWaste (CC BY 4.0, already the photo source). Category →
  expected gate outcome: Metal, Glass → REJECT (hard contaminant);
  Food Organics, Vegetation → ESCALATE (wet/organic);
  Paper, Cardboard, Plastic, Textile → ACCEPT. ~80 images, stratified,
  list + licence in `benchmark/manifest.csv`.
- **Honest framing**: "component validation of the vision gate on public
  RealWaste images — not field data from a plant." Stated wherever the
  numbers appear.
- `benchmark/run.py`: runs each image through the *real* `/inspect` pipeline
  live on AMD, throttled for the shared key, resumable; writes
  `benchmark/results/<date>.json` (per-item verdict, latency, model ids).
- **Metrics**: REJECT precision/recall/F1, 3×3 confusion matrix, latency
  p50/p95. Published in README, a `/validation` page, and the deck.
- **Time saving**: Lynceus p50 latency vs. a manual visual check time
  *from a cited source*; if no citable source is found, report Lynceus
  latency alone — no invented baseline.

### 4.8 Engine and UI hardening (in scope, small)

- Engine: `decision.py` reads `insufficient` instead of the never-serialised
  `actionable`; explicit tie-break margin in route scoring.
- Web: memoise gate normalisation (gate strip replay bug), single detail panel
  on mobile, real error messages instead of "Backend unreachable" for 4xx/5xx,
  remove dead code listed in the study notes.
- Upload limits: max decoded photo size 8 MB, enforced server-side with HTTP 413.

## 5. Data flow (one truck)

```
operator submits photo + waybill + weight + supplier
  → audit.begin_record (inputs frozen + digested)
  → gas: live sensor gateway or physics twin (labelled)
  → VLM @ AMD: contaminants + boxes + moisture + confidence
  → LLM @ AMD: waybill fields + claim-vs-observation crosscheck
  → engine (route scores) → decision.decide → actions.py (SOP-cited steps)
  → audit.finish_record (v2) → impact estimate
UI: gates light → verdict → boxes on photo → next-step card → "Ask Pythia"
supervisor: /shift aggregates records → supplier ranking + explanation
```

## 6. Delivery and submission

- **Live URL**: single container (existing `Dockerfile`: FastAPI + static web)
  on a Docker host (Render / Railway / HF Spaces — chosen in the plan on
  cold-start and secret-handling). Key in host secrets, never in the repo.
- **Video** 3–5 min (under 3 is penalised): problem 0:00–0:30 → live demo
  of all three verdicts, boxes, next step, Pythia, shift report 0:30–2:45 →
  benchmark numbers → business case, market, competitors, revenue → roadmap.
  AMD provenance visible on screen.
- **Deck** PDF 8–10 slides incl. market analysis, competitive analysis,
  revenue model, roadmap (rubric 5/5 requires these).
- **Cover** 16:9; title ≤ 50 chars; short description ≤ 255; long ≥ 100 words.
- **Repo**: README runs from a fresh clone; LICENSE (MIT) present; steady
  commits through the event window.
- **Team admin (human action)**: every member signed up via "Sign up with AMD"
  and in the AMD AI Developer Program.

## 8. Testing

- Backend: pytest per new module (`actions`, `vision_boxes`, `assist`
  retrieval + citation check, `shift`, audit v2 read/write, gas no-data path);
  VLM/LLM clients tested with recorded fixtures; live smoke stays opt-in
  (`LYNCEUS_LIVE_TESTS=1`).
- Web: `tsc --noEmit`, `next build`, zod contracts for every new endpoint.
- End-to-end: scripted smoke over the golden path against the deployed URL
  before recording.
- Benchmark is reproducible from the manifest and committed results.

## 9. Open risks

- Token Factory vision localisation quality (mitigated: zone fallback).
- Shared-key rate limits during benchmark and judging (mitigated: throttling,
  `Retry-After`, scripted samples always available, results cached).
- Gemma text quality (mitigated: DeepSeek fallback; Google prize is a bonus).
- Hosted cold start during judging (mitigated: host choice + keep-alive).
