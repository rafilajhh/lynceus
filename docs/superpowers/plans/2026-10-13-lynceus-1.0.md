# Lynceus 1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Lynceus from a verdict-only gate inspector into a Track 1 product that tells the operator *what to do next*, answers from plant documents, explains the shift, and proves its accuracy — all inference live on AMD.

**Architecture:** Additive modules beside the existing FastAPI pipeline (`backend/src/lynceus/`): `vision_boxes`, `actions`, `kb` + `assist` (Pythia), `shift`, and a `benchmark/` harness. Audit record goes to format v2 (reads v1). The Next.js static console gains photo evidence, a next-step card, a Pythia panel, `/shift` and `/validation` routes.

**Tech Stack:** Python 3.12, FastAPI, pydantic v2, httpx, pytest; Next.js 15 (App Router, static export), React 19, Tailwind v4, zod 4; AMD Token Factory (OpenAI-compatible).

**Spec:** `docs/superpowers/specs/2026-10-13-lynceus-1.0-design.md`

**Worktree / branch:** `D:\project lock in\amd act 3\lynceus\.claude\worktrees\lynceus-1.0` on `feat/lynceus-1.0`. All paths below are relative to it. Backend commands run from `backend/`, web commands from `web/`.

## Global Constraints

- Every model call goes through the OpenAI-compatible client configured by env; the submitted config points all roles at AMD Token Factory. No Gemini proxy in any committed config or doc.
- Secrets only in `backend/.env` or host secrets; never committed, never logged, never in API responses.
- Honesty labels: scripted data says "Scripted sample"; seeded shift says "Sample shift — scripted data"; benchmark says "component validation on public RealWaste images — not field data from a plant"; the reference SOP says "reference SOP".
- No new runtime dependencies (BM25 and stats in pure Python). No vector DB, no numpy.
- Audit invariants of `audit.py` docstring (lines 15–51) stay true; writer emits `format_version: 2`, reader accepts 1 and 2.
- UI follows `DESIGN.md`: dark graphite surfaces, single amber accent for state only, verdict colours carry meaning only, IBM Plex Sans/Mono, no shadows/glass/gradient text/emoji, buttons only via existing cva variants. English UI copy.
- Gate names stay the closed set `vlm_confidence, ocr_confidence, manifest_crosscheck, gas_plausibility, weight_plausibility`.
- Commit after every task; push `feat/lynceus-1.0` at the end of each day. Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Garbage localisation from the VLM** (boxes out of range, inverted, 50 boxes, strings) → inspection still completes, bad boxes silently dropped. Pinned in Task 4.
2. **Pre-v2 records on disk** (21 v1 records today) → still listed in the ledger, readable in detail, counted in the shift report with supplier "unknown". Pinned in Tasks 3 and 9.
3. **Pythia asked something the documents don't cover, or a waybill containing "ignore previous instructions"** → no uncited claim; Pythia says it cannot answer from the plant documents. Pinned in Task 7.
4. **Oversized or non-image upload** → HTTP 413 / 422 with a readable message, no orphaned `in_progress` record. Pinned in Task 12.
5. **Token Factory 429 / outage mid-benchmark or mid-demo** → benchmark resumes where it stopped; live inspection fails closed (503) or falls back with honest provenance per config. Pinned in Tasks 2 and 11.
